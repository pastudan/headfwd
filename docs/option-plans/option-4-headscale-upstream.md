# Option 4: Upstream to Headscale

## Goal
Partner with headscale maintainers to integrate headfwd functionality natively or as an endorsed optional module.

## Why this matters
- Major credibility boost and community distribution.
- Reduces long-term integration friction.
- Aligns with headscale’s ecosystem and user base.

## Scope (MVP)
- Define a minimal, opt-in integration design.
- Demonstrate self-hostable workflow without headfwd.net.
- Prepare a short pitch and working demo.

## Milestones
- Draft a 1-page proposal and integration sketch.
- Create a demo that proves the flow.
- Get maintainer feedback on scope and alignment.
- Submit a minimal PR or RFC if aligned.

## Success criteria
- Maintainers express interest and see alignment.
- Clear path to an opt-in integration.
- Agreement on constraints and hosting neutrality.

## Risks
- High bar for acceptance and long review cycles.
- Maintainers may avoid vendor-specific workflows.
- Roadmap mismatch could stall progress.

## Open questions
- What is the smallest change that still adds user value?
- What UX or security concerns might maintainers raise?
- How to avoid coupling to a hosted service?

## Next steps
- Draft the pitch and positioning.
- Prepare demo narrative and screen recording.
- Engage maintainers with feedback-first outreach.
