# HeadFwd

a universal access pattern for any self-hosted app

# Launch Strategy

## Positioning

Present as a **"self-hosted media platform with a unified access API"** — not just a single app.

The iOS app and backend are the reference implementation of a broader system.

### Key Framing

> "I've been building a way to access your self-hosted apps from anywhere, without relying on cloud services.
>
> Here's what you get:
>
> 1. An iOS app that connects directly to your home server
> 2. A backend that runs on your hardware (Raspberry Pi, NAS, whatever)
> 3. A standardized API that ties them together
>
> The first implementation is a music server — point it at your library, stream from anywhere through your own infrastructure. But the API is open, so anyone can build backends for other types of media or data."

This positions it as an extensible **system**, giving permission for others to extend it.

---

## Safe Extensibility Language

Hint at broader use without naming risky examples

**Use:**

- "Backends are modular. The included one serves local media, but the API is open — anyone can build adapters for other sources."
- "Each backend simply implements the same standardized schema and auth layer."
- "Future backends could index or cache from any data source the user controls."

---

## Launch Components

Launch both together as a cohesive vision:

1. **iOS app**: clean, minimal client
2. **Backend**: reference self-hosted app
3. **"Remote Access Framework"**: the standardized API layer tying them together
